# Foundational Infrastructure Working Group Update

Since the [June 22 draft](https://github.com/cloudfoundry/community/blob/e1010e6c03e20b32269bb52cd30320ed27b9fd96/toc/working-groups/updates/2026-06-22-foundational-infrastructure.md), the Ubuntu 26.04 LTS BOSH stemcell reached GA and BOSH gained upstream artifacts for air-gapped Google Distributed Cloud. The group is also reviewing changes to how BOSH supervises jobs and exposes health events, and looking for ways to run fewer CI pipelines and test environments.

## Ubuntu 26.04 LTS (Resolute Raccoon)

The BOSH stemcell reached the [Resolute 1.x release line](https://github.com/cloudfoundry/bosh-linux-stemcell-builder/releases/tag/ubuntu-resolute/v1) and is [documented as GA](https://github.com/cloudfoundry/docs-bosh/pull/943), advancing [RFC-0058](../../rfc/rfc-0058-resolute-raccoon-os.md). [BOSH Director v283.0.0](https://github.com/cloudfoundry/bosh/releases/tag/v283.0.0) added compatibility, and `bosh-deployment` added [Resolute ops files](https://github.com/cloudfoundry/bosh-deployment/pull/520) and [test jobs](https://github.com/cloudfoundry/bosh-deployment/pull/522). The [BOSH Agent](https://github.com/cloudfoundry/bosh-agent/pull/455), [BPM](https://github.com/cloudfoundry/bpm-release/pull/230), and [BOSH DNS](https://github.com/cloudfoundry/bosh-dns-release/pull/174) added test coverage, and [syslog-release](https://github.com/cloudfoundry/syslog-release/pull/259) removed its dependency on `chpst`. Stemcell GA is a BOSH milestone; [validation of the full `cf-deployment` stack](https://github.com/cloudfoundry/cf-deployment/issues/1374) is still open. Operators upgrading to BOSH 283 should also check that their CPI supports v2, since 283 removed CPI v1 support.

## BOSH and cloud infrastructure

- **Air-gapped Google Distributed Cloud:** [RFC-0063](../../rfc/rfc-0063-gdc-cpi-and-stemcell-builder.md) was accepted, and Google and SAP established a [new FI area](https://github.com/cloudfoundry/community/pull/1648) to maintain the CPI. The upstream [GDC CPI v0.1.4](https://bosh.io/releases/github.com/cloudfoundry/bosh-gdc-cpi-release?version=0.1.4) is published on bosh.io, and the stemcell builder shipped [GDC support for Ubuntu Noble](https://github.com/cloudfoundry/bosh-linux-stemcell-builder/releases/tag/ubuntu-noble/v1.664). Two [backup maintainers](https://github.com/cloudfoundry/community/pull/1716) joined the area. The [implementation tracker](https://github.com/cloudfoundry/community/issues/1654) remains open.
- **ARM64:** With [RFC-0062](../../rfc/rfc-0062-arm64-support.md) accepted, [ARM64 stemcell builds](https://github.com/cloudfoundry/bosh-linux-stemcell-builder/pull/768) and [BOSH Agent builds](https://github.com/cloudfoundry/bosh-agent/pull/493) merged. [Director packaging and CI](https://github.com/cloudfoundry/bosh/pull/2845) are still under review; this is not yet end-to-end ARM64 support.
- **Dynamic disks and dual-stack networking:** BOSH Director [v283.1.2](https://github.com/cloudfoundry/bosh/releases/tag/v283.1.2) shipped the create, attach, and list endpoints for dynamic disks. The [CLI commands](https://github.com/cloudfoundry/bosh-cli/pull/728) and [operator documentation](https://github.com/cloudfoundry/docs-bosh/pull/927) merged; [RFC-0053 delivery tracking](https://github.com/cloudfoundry/community/issues/1460) is still open. [Azure CPI v53.1.9](https://github.com/cloudfoundry/bosh-azure-cpi-release/releases/tag/v53.1.9) shipped VM dual-stack support, and [AWS CPI v107.3.5](https://github.com/cloudfoundry/bosh-aws-cpi-release/releases/tag/v107.3.5) added primary IPv6 addresses on network interfaces.

## BOSH modernization proposals

- **Health Monitor rewrite and plugin replacement:** A [draft BOSH PR](https://github.com/cloudfoundry/bosh/pull/2747) ports the Ruby Health Monitor to Go. The separate [Health Monitor event-log RFC](https://github.com/cloudfoundry/community/pull/1671) proposes replacing notification plugins and executable hooks with a versioned JSON event log read by independent collectors. Resurrection and Director event recording would stay built in. Plugin removal would wait for a working replacement and a tested collector example. Operators using custom hooks or integrations should flag them on the RFC.
- **Replacing Monit:** The [job supervision RFC](https://github.com/cloudfoundry/community/pull/1706) proposes an opt-in path on Resolute where systemd supervises jobs through BPM, using the existing `bpm.yml`. Monit and BPM-supervised jobs could coexist during migration. The proposal calls for deprecating Monit once the new path is GA and removing it in a later major stemcell line. Feedback on custom Monit checks and support for older stemcells would help.
- **Deprecating the VirtualBox and Warden CPIs:** The [CPI deprecation RFC](https://github.com/cloudfoundry/community/pull/1702) proposes standardizing local development and CI on the Docker CPI, then stopping releases, removing CI pipelines, and archiving both legacy CPI repositories after a three-month deprecation period. The BOSH team reports it has migrated its Warden pipelines; the RFC calls for moving any remaining App Runtime Deployments pipelines. Flag any workflows that still need VirtualBox or Warden.

## Reducing the CI/CD footprint

- **Already consolidated:** BOSH [moved disaster-recovery acceptance tests to the Docker CPI](https://github.com/cloudfoundry/bosh/pull/2808) and [trimmed their duplicate standalone Concourse jobs](https://github.com/cloudfoundry/bosh-disaster-recovery-acceptance-tests/pull/249). The [Backup and Restore SDK pipeline](https://github.com/cloudfoundry/backup-and-restore-sdk-release/pull/1917) moved to community Concourse with short-lived test directors, and [OpenStack CPI CI](https://github.com/cloudfoundry/bosh-openstack-cpi-release/pull/338) replaced a persistent external cloud with a disposable DevStack per run.
- **Concrete follow-ups:** `bosh-deployment-resource` added [Docker CPI acceptance tests in GitHub Actions](https://github.com/cloudfoundry/bosh-deployment-resource/pull/116); moving release publishing is a proposed follow-up. The stemcell team has an [open proposal to evaluate moving Concourse pipelines to GitHub Actions](https://github.com/cloudfoundry/bosh-linux-stemcell-builder/issues/738), starting with a pipeline inventory and a prototype. A key question is how to preserve traceability from an Ubuntu security notice to a published stemcell. At the WG, agree which duplicate jobs can be retired and which tests can use short-lived Docker CPI environments, while preserving real-cloud coverage for provider-specific behavior.

## Identity, storage, and recovery

- **Identity:** UAA shipped [mTLS token endpoint hardening in v79.10.0](https://github.com/cloudfoundry/uaa/releases/tag/v79.10.0) and [subject matching for federated clients in v79.11.0](https://github.com/cloudfoundry/uaa/releases/tag/v79.11.0); [UAA Release v79.12.0](https://github.com/cloudfoundry/uaa-release/releases/tag/v79.12.0) also updated Java and Tomcat. The cross-group [workload service accounts RFC](../../rfc/rfc-0065-service-accounts.md) was accepted; the [Cloud Controller implementation](https://github.com/cloudfoundry/cloud_controller_ng/pull/5520) and [RFC amendments](https://github.com/cloudfoundry/community/pull/1709) are still open. CredHub merged [duration validation for certificate regeneration](https://github.com/cloudfoundry/credhub/pull/1234).
- **Storage and recovery:** The [Cloud Controller storage CLI tracker](https://github.com/cloudfoundry/community/issues/1274) closed after all five backends were documented as delivered in `cf-deployment`. The separate [BOSH Director storage CLI integration](https://github.com/cloudfoundry/bosh/pull/2665) is still a draft. [Postgres Release v57.0.0](https://github.com/cloudfoundry/postgres-release/releases/tag/v57.0.0) added compatibility for PostgreSQL 16–18 on Ubuntu Resolute, and [Backup and Restore SDK v1.20.4](https://github.com/cloudfoundry/backup-and-restore-sdk-release/releases/tag/v1.20.4) added PostgreSQL 18 support.

## Platform logging

[RFC-0064](https://github.com/cloudfoundry/community/issues/1697) was accepted for opt-in OpenTelemetry collection of platform logs. Syslog remains the default, and operators can run both during migration.
